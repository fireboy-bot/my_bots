## 🛠 Правила разработки (Напоминание)

### 🔹 Git-процесс
- `master` = только стабильно. Вся разработка → в ветки `feature/...`, `fix/...`
- Один коммит = одна логическая задача. Формат: `type: описание`
- Перед коммитом: проверяй `git status`. Не коммить `.env`, `*.db`, `logs/`, `__pycache__/`, `node_modules/`
- После мержа фичи: `git branch -d feature/...`
- Теги для версий: `git tag -a vX.Y-stable -m "описание"`

### 🔹 Безопасность
- `.env` никогда не коммитится. В репо только `.env.example`
- Перед отправкой кода в ИИ: удаляй токены, пути к серверам, тестовые ФИО
- `parent_email` шифруется через `cryptography.fernet` (152-ФЗ)
- Бэкапы БД (`*.db`) не коммитятся. Делай регулярные снепшоты перед обновлениями

### 🔹 Качество кода
- Формат: PEP 8, типизация (`typing`), docstrings
- Архитектура: ядро не знает про платформы, адаптеры не знают про бизнес-логику
- Тесты: критичные пути (`solve_task`, `upgrade_artifact`, `send_message`) покрывать юнит-тестами
- Логи: `INFO` для событий, `WARNING` для деградации, `ERROR` только для исключений
