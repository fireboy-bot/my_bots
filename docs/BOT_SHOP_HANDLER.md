## 📋 Обзор

`shop.py` — модуль управления магазином «Числяндии». Поддерживает две категории товаров:

| Категория | Тип | Примеры | Механика |
|-----------|-----|---------|----------|
| 🧪 Зелья | `consumable` | Зелье Здоровья, Зелье Мудрости | Покупка → добавление в `inventory[]` |
| ⚡ Артефакты | `artifact` | Артефакт Удачи, Артефакт Силы | Покупка/улучшение → рост уровня, динамическая цена |

**Ключевые особенности:**
- ✅ Аватарка Торговца при входе в магазин
- ✅ Динамическое ценообразование артефактов: `base_price × multiplier^level`
- ✅ Комментарии Владимира при покупках (если замок открыт)
- ✅ Адаптер-паттерн: поддержка Telegram + VK/MAX
- ✅ Логирование покупок через `log_user_action()`

## ⚙️ Основные функции

### `show_shop(update, context)`
Показывает главное меню магазина с аватаркой Торговца.

**Логика:**
1. Получает `adapter` и `storage` из `bot_data`
2. Логгирует действие: `log_user_action(user_id, "SHOP_OPEN")`
3. Формирует сообщение с балансом и категориями
4. Отправляет аватарку Торговца через `send_character_message("shop_keeper", ...)`
5. Показывает клавиатуру с категориями: `["🧪 Зелья", "⚡ Артефакты", "⬅️ Назад"]`

**Пример сообщения:**
```
🛒 *ДОБРО ПОЖАЛОВАТЬ В МАГАЗИН!*

💰 *Ваш баланс:* 1 250 золотых

*Категории:*
🧪 Зелья и расходуемые предметы
⚡ Артефакты (прокачиваемые бонусы)

Выберите категорию:
```

### `show_potions(update, context)`
Показывает список зелий для покупки.

**Логика:**
1. Фильтрует `SHOP_ITEMS` по `type == "consumable"`
2. Проверяет доступность: `✅` если `balance >= price`, иначе `❌`
3. Формирует клавиатуру: одна кнопка на предмет + "Назад"
4. Отправляет сообщение с ценами и подсказкой

**Пример:**
```
🧪 *ЗЕЛЬЯ И РАСХОДУЕМЫЕ ПРЕДМЕТЫ*

✅ Зелье Здоровья — 100 золотых
❌ Зелье Мудрости — 500 золотых

_Нажми на предмет для покупки_
```

---

### `show_artifacts(update, context)`
Показывает артефакты с **динамическим ценообразованием**.

**Формула цены:**
```python
if current_level == 0:
    price = base_price  # например, 500
else:
    price = int(base_price * (cost_multiplier ** current_level))
    # например: 500 × 1.4^2 = 980 золотых за уровень 2→3
```

**Логика:**
1. Получает текущие уровни из `user_data["artifact_upgrades"]`
2. Для каждого артефакта рассчитывает цену следующего уровня
3. Показывает статус: `❌ Не куплен` или `✅ Уровень N`
4. Формирует клавиатуру с названиями артефактов

**Пример:**
```
🔮 *АРТЕФАКТЫ (ПРОКАЧИВАЕМЫЕ БОНУСЫ)*

✅ Артефакт Удачи
   ✅ Уровень 2 | 💰 980 золотых
   _Эффект: +10% к удаче при решении задач_

❌ Артефакт Силы
   ❌ Не куплен | 💰 750 золотых
   _Эффект: +5 очков за правильный ответ_
```

### `buy_item(update, context)` — 🎯 Ключевая функция
Обрабатывает покупку предмета или улучшение артефакта.

**Алгоритм:**

```
1. Получить название предмета из update.message.text
2. Найти предмет в SHOP_ITEMS или ARTIFACTS
3. Проверить баланс: если < цены → ошибка
4. Если артефакт:
   ├─ Вызвать engine.upgrade_artifact(user_id, artifact_id)
   ├─ Если успех → обновить UI, показать сообщение
   └─ Если ошибка → показать причину
5. Если обычный предмет:
   ├─ Списать баланс
   ├─ Добавить item_id в user_data["inventory"]
   └─ Сохранить пользователя
6. Если замок открыт → Владимир комментирует покупку
7. Показать главное меню
```

**Особенности обработки артефактов:**
- Используется `engine.upgrade_artifact()` — единая точка улучшения
- Цена рассчитывается автоматически внутри `upgrade_artifact()`
- После покупки обновляется `artifact_upgrades[user_id][artifact_id] += 1`

**Комментарии Владимира:**
```python
if phrase_manager.is_castle_unlocked(user_data):
    # Особые фразы для "рискованных" предметов
    if "Безум" in item["name"]:
        phrase = "«Зелье Безумия?.. Я уже приготовил совок...»"
    elif "Смел" in item["name"]:
        phrase = "«Зелье Смелости?.. Надеюсь, вы знаете что делаете...»"
    # ...другие условия
    else:
        phrase = phrase_manager.get_vladimir_phrase("purchase_decoration")
    
    await send_character_message(update, context, "vladimir", phrase, mood="approve")
```

### `handle_shop_callback(update, context)`
Обрабатывает inline-кнопки магазина (для будущего расширения).

**Формат `callback_data`:**
```
buy_item|id:potion_health|qty:1
```

**Логика:**
1. Парсит `data` на части: `id`, `qty`
2. Находит предмет в `SHOP_ITEMS`
3. Проверяет баланс × количество
4. Списывает средства, добавляет в `inventory`
5. Обновляет сообщение с подтверждением

> ⚠️ Сейчас используется редко — основной поток через текстовые кнопки.

### `get_shop_handlers()`
Возвращает список хендлеров для регистрации в `manyunya_bot.py`.

```python
def get_shop_handlers():
    return [
        CommandHandler("shop", show_shop),
        MessageHandler(filters.Text("🧪 Зелья") & ~filters.COMMAND, show_potions),
        MessageHandler(filters.Text("⚡ Артефакты") & ~filters.COMMAND, show_artifacts),
        MessageHandler(filters.Text("⬅️ Назад") & ~filters.COMMAND, back_to_menu),
        MessageHandler(
            filters.TEXT & ~filters.COMMAND & 
            (filters.Text("🧪 Зелье Здоровья") | ...),  # список предметов
            buy_item
        ),
    ]
```

> ⚠️ **Важно:** Фильтры `filters.Text(...)` чувствительны к регистру и пробелам. При изменении названий в `items.py` — обновлять здесь!

## ⚠️ Важные замечания

### 1. Динамическое ценообразование артефактов
Цена рассчитывается **на лету** при отображении и покупке:
```python
price = int(base_price * (cost_multiplier ** current_level))
```
- Убедись, что `cost_multiplier` задан в `ARTIFACTS` (по умолчанию `1.4`)
- При изменении формулы — обновляй в `show_artifacts()` и `buy_item()`

### 2. Инвентарь: обычные предметы vs артефакты
| Тип | Где хранится | Как используется |
|-----|-------------|-----------------|
| 🧪 Зелья | `user_data["inventory"]` (список ID) | Расходуется через `effects_manager.py` |
| ⚡ Артефакты | `user_data["artifact_upgrades"]` (dict: `{id: level}`) | Бонусы применяются через `score_manager.py` |

### 3. Комментарии Владимира
- Срабатывают **только** если `phrase_manager.is_castle_unlocked(user_data) == True`
- Для "рискованных" предметов (`Безум`, `Смел`, `Судьб`) — особые фразы
- Если замок закрыт — показывается стандартное сообщение без персонажа

### 4. Адаптер-паттерн
Все отправки сообщений идут через `adapter.send_message()`, а не напрямую `update.message.reply_text()`. Это обеспечивает совместимость с Telegram и VK/MAX.

### 5. Логирование
Все покупки логируются:
```python
log_user_action(user_id, "ITEM_PURCHASED", f"item={name}, price={price}")
log_user_action(user_id, "ARTIFACT_PURCHASED", f"artifact={id}, price={price}")
```
Проверяй логи в `logs/app.log` при отладке.
